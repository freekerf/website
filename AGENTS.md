# FreeKerf website: maintenance guide

For people and coding agents working on this repository. `CLAUDE.md` only includes
this file. The plan (what to build, milestones) is [`PLAN.md`](PLAN.md); this guide is
how to work on what exists.

## Overview

The public site of FreeKerf: the entry point to the app. Today it is milestone 1 of
the plan: a landing page and a download page, in English and Brazilian Portuguese,
on GitHub Pages. The user guide drafted in `src/content/docs/` is **not published
yet** (milestone 3).

Static site with [Astro](https://astro.build) ([ADR 0001](doc/adr/0001-site-generator.md)),
no client framework: a few lines of inline JavaScript for the theme and the download
picker, and the pages work without them.

## Layout

```
src/pages/            routes: index, download, pt-br/index, pt-br/download, 404 (thin: they pick a locale)
src/views/            the pages, written once for every locale (Landing, Download)
src/layouts/Base.astro  head (meta, hreflang, theme), header, footer
src/components/       Header, Footer, Logo, Screenshot
src/lib/              pure logic, unit tested: i18n.ts (paths, strings), releases.ts (parsing, OS, installers)
src/data/releases.ts  the releases read once per build (GitHub API, or a fixture)
src/i18n/             strings: en.ts (source), pt-br.ts
src/site.ts           project links
src/styles/           site.css (hand-written) and fk-tokens.css (generated, do not edit)
src/assets/screenshots/  app screenshots (generated by `npm run screenshots`, do not edit)
src/content/docs/     user guide drafts (milestone 3, not built yet)
public/               fonts, favicon and logos synced from freekerf/design (do not edit)
scripts/              sync-design.mjs, screenshots.mjs, lib/ (pure, unit tested)
tests/unit/           Vitest: lib and scripts/lib
tests/integration/    Vitest: full builds with recorded releases, design sync check
tests/e2e/            Playwright: navigation, language switch, download picker, axe
tests/fixtures/       recorded GitHub releases answers
doc/                  documentation about the site (below)
design.lock           the freekerf/design commit the design files come from
```

## Commands

```bash
npm ci                                # once (Node ≥ 22.22, CI uses 24)
npm run dev                           # http://localhost:4321/website/
npm run build                         # dist/ (reads the releases from GitHub)
FK_RELEASES_OFFLINE=1 npm run build   # no network: the download page says it could not read them
npm run preview                       # serve dist/
npm run check                         # astro check (types in .astro and .ts)
npm test                              # unit + integration (two full builds, ~30 s)
npm run coverage                      # the same with coverage (src/lib, scripts/lib ≥ 90 % lines)
npm run test:e2e                      # Playwright; locally PW_CHANNEL=msedge or PW_CHROMIUM=<path>
npm run validate:html                 # html-validate on dist/ (after a build)
npm run sync:design                   # design files at design.lock (../design or FREEKERF_DESIGN)
npm run sync:design -- --check        # CI: committed == generated
npm run screenshots                   # app screenshots (needs the app's dev.html, doc/features/screenshots.md)
```

## Content rules

- **No hard-coded versions, installer names or URLs that can be derived.** Versions and
  installers come from the releases; project links from `src/site.ts`.
- **Every string in every locale.** Add the key to `src/i18n/en.ts`, then to every other
  locale (the type and `tests/unit/i18n.test.ts` fail otherwise). Placeholders `{name}`
  are kept. Voice and tone: `design/brand/brand.md` ([`doc/content-guide.md`](doc/content-guide.md)).
- **The name is FreeKerf**, one word, F and K capital (tested).
- **The project FreeKerf grows from is credited, not promoted**: one line in the footer.
  The site presents FreeKerf on its own terms.
- **Screenshots are generated from the app**, never edited by hand, in both themes.
- **Features are not documented on the landing**: the user guide (milestone 3) does that.
- **Accessibility**: semantic HTML, one `h1` per page, visible focus, `alt` on every
  screenshot, colours only from `--fk-*` tokens (contrast measured in `design`).
- **Privacy**: no cookies, no trackers, no third-party requests at runtime
  ([ADR 0003](doc/adr/0003-no-analytics.md)).

## Testing rules

- New logic goes in `src/lib/` or `scripts/lib/` as pure functions, with unit tests;
  coverage of those folders stays ≥ 90 % lines (CI fails below).
- The release fetcher is tested against `tests/fixtures/`, never the live API in CI; a
  scheduled job checks the live API and external links.
- No sleeps in end-to-end tests: wait on locators.
- A new page gets: its route for every locale, a line in `PAGES` of `tests/e2e/site.spec.ts`
  (axe at three widths and two themes), and an integration assertion.

## Conventions

- English for code, comments, docs, commits and PRs. Commit subjects in the imperative.
- Prettier-like formatting (2 spaces, single quotes, 120 columns), as in the existing files.
- Work on a branch; PRs against `freekerf/website` `main`.
